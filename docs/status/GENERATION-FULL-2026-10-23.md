# 全量生成 + 生成页交互调整（2026-10-23）

## 问题

- pc-admin 还没有真正做过整个项目的用例生成。
- 页面默认按单个 Tag（2.2.1）生成，只能得到局部用例。
- 原“当前被测对象 · 生成轴心”把项目生成误导成单分支/单 Tag。
- 页面同时存在覆盖计划、服务勾选、生成轴心、批次、审核等多套信息，主操作不清晰。

## 调整

### 两种生成模式

- **全量生成（项目）**：默认模式
  - 自动包含项目下全部已确认服务
  - 每个服务使用其仓库默认分支的最新提交
  - 不使用单个 Tag 代表全项目
  - 每次点击都会创建新批次（idempotency key 每次 UUID）
- **指定服务**：
  - 手动勾选服务
  - 逐服务选择分支或 Tag
  - 适合局部复测

### 页面交互

- 顶部新增“生成模式”卡片：
  - 模式切换
  - 范围摘要：服务数、仓库数、代码引用方式
  - 明确“可重复生成”
- 主按钮在 full 模式显示“全量生成用例（N）”
- 全量模式下：
  - 服务列表自动全选并禁用勾选
  - 隐藏“生成轴心”中的 Tag/分支选择卡，避免误导为单 Tag 生成
  - 确认面板显示“默认分支”，不再要求逐服务选 Tag
- 指定服务模式保留原先的分支/Tag 选择。

## 0.1.127 进一步调整

- 真实项目只保留服务复选框作为唯一选择源；真实模式不再渲染“生成轴心”服务下拉。
- 全量模式不再展示复选框列表，改为全量摘要（服务/仓库/DSH 任务数 + 服务标签）。
- 真实模式完全隐藏分支/Tag 轴心卡。
- 页面底部固定生成操作条，显示服务数、代码引用方式、批次数和 DSH 任务数。

## 当前机制

- 全量生成仍按“一个服务一个批次”创建；27 个服务会产生 27 个批次/DSH job。
- 每次全量操作生成新批次，旧批次保留审计。
- 候选仍需人工审核后入库。
