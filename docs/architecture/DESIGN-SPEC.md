# GreenPass 设计规范（Design Spec）

> 版本 v1.0 · 2026-09-28
> 目的：为本原型确立**可执行的交互与 UI 标准**，统一设计语言，避免功能堆砌、卡片堆砌、视觉漂移。本规范以「被测对象页」为样板落地，验证通过后推广到全部页面。

---

## 1. 设计原则（判断一切设计的最高准则）

| 原则 | 含义 | 反例 |
|---|---|---|
| **一页一焦点** | 每个页面只有一个视觉/交互焦点；其余内容是它的关联，折叠或次级呈现 | 一页堆 6 张等大卡片，不知先看哪 |
| **状态可见** | 每个对象（被测对象/批次/用例/执行/环节）都明确"当前处于什么状态" | 点了按钮只有 toast，看不到状态演进 |
| **反馈闭环** | 操作 → 状态变化 → 可继续操作；不静默 | 点击后无任何变化 |
| **一致设计语言** | 颜色/间距/圆角/字号/图标/卡片全站统一（本规范 token） | 各页标题、按钮、徽章风格漂移 |
| **密度匹配场景** | 总览疏、清单适中、详情密 | 详情页挤满 / 总览页空洞 |
| **语义用色克制** | 绿=成功/主操作，红=失败/阻断，琥珀=警告；选中与链接统一主色 | 到处用绿色、到处用彩色 |

## 2. 设计 Token（全站统一变量）

### 2.1 颜色
| 用途 | 色值 | 说明 |
|---|---|---|
| 品牌/主操作 | emerald-600 `#059669` | 主按钮、主卡、选中态、核心高亮 |
| 品牌渐变 | emerald-500 → teal-700 | 品牌卡、对象主卡、Logo |
| 主色浅底 | emerald-50 `#ecfdf5` | 成功徽章底、选中浅底 |
| 警告 | amber-500/600 | 待处理、部分完成、CI 未运行 |
| 失败/阻断 | red-500/600 | 失败、阻断、缺口 |
| 中性文本 | slate-700（主）/500（次）/400（弱） | 正文层级靠字色分 |
| 中性背景 | slate-50（页）/slate-100（控件底） | 背景层 |
| 边框 | slate-200 | 分隔 |
| 禁用/占位 | slate-300 | 弱化 |

> 样板页内统一：选中、链接、主按钮只用 emerald；信息/中性一律 slate；红/琥珀仅表失败/警告。逐步淘汰 indigo 作为选中/链接色（推广阶段替换）。

### 2.2 间距（4px 网格）
- 页面 padding：24（main 容器）
- 区块间距：20–24
- 卡片内 padding：16（紧凑）/ 20（常规）/ 24（焦点卡）
- 表行高：32–40；表格单元格 padding 垂直 10–12
- 网格 gap：8/12/16/20/24 五档

### 2.3 圆角
- 卡片：12–16（焦点卡 16，常规卡 12）
- 按钮：8–10
- 输入框/下拉：8
- 徽章：全圆（rounded-full）
- 图标容器：8–10
- 标签/步骤节点：全圆

### 2.4 字号与字重
| 层级 | 字号/字重 | 用途 |
|---|---|---|
| 页面标题 | 16 semibold | PageHeader title |
| 卡片标题 | 14 semibold | 卡片 h2 |
| 正文 | 12–13 | 表格、段落 |
| 辅助/说明 | 10–11 | desc、meta、注释 |
| 数据/代码 | 11–12 mono | 版本、ID、数字 |
| 焦点大数字 | 28–32 bold | 质量评分、风险数 |

### 2.5 阴影
- 常规卡片：无边框外阴影（仅 `border-slate-200`）
- hover 反馈：`shadow-sm` + 上浮 2px（可选）
- 弹窗/下拉：`shadow-lg`/`shadow-2xl`
- 主操作/选中：`shadow-md`（emerald 投影，如 `shadow-emerald-200`）

### 2.6 图标
- 统一 lucide；菜单各层图标唯一（已有）
- 图标容器统一：24–36px、对应圆角、浅底 + 主色图标
- 语义图标：状态用 CircleCheckBig/CircleX/CircleAlert；方向用 ChevronRight/ArrowRight；对象用 Crosshair/Layers

## 3. 交互规范

### 3.1 状态体系（全局统一的对象状态模型）
每个核心对象必须有一个**明确的当前状态**，用统一语义色 + 文字表示：
| 状态 | 色 | 示例 |
|---|---|---|
| 待办/未开始 | slate-300 | 环节未触达 |
| 进行中 | emerald-500 + 实心点 | 生成流程当前步骤、任务运行 |
| 已完成/通过 | emerald-600 | 环节完成、门禁通过 |
| 待处理/部分 | amber-500 | 有风险、部分覆盖 |
| 失败/阻断 | red-600 | 门禁阻断、覆盖缺口 |
| 已回退 | slate-400 + 撤销图标 | 用例版本回退 |

> 状态必须**可见**（不能只靠点击才知道）：环节条、批次、用例、执行都要标注状态。

### 3.2 反馈闭环
- 一切操作必有反馈：瞬时反馈（选中高亮/按钮态）+ 结果反馈（状态变化或 toast，toast 只用于一次性成功提示）。
- 破坏性操作（删除/回退/剔除）需二次确认。
- 异步/进行中：按钮 loading 态 + 对象状态点。

### 3.3 导航与层级（心智模型）
- **全局被测对象轴心**：页首面包屑（可切换）+ 层次筛选，全站跟随。
- **一页一焦点**：主内容区一个焦点卡；其余环节折叠为**状态条/步骤条**（不铺开）。
- 面包屑可点开切换同级/进入子级（已有，保留并统一主色）。
- 列表页统一：查询条件区 + 表格 + 底部计数。

### 3.4 动效（克制）
- hover：边框/浅底/阴影 轻反馈，150–200ms。
- 选中/切换：200–250ms ease。
- 弹窗/下拉：淡入 + 微上浮。
- 不堆砌动画；无装饰性空转动画。

### 3.5 空态 / 加载 / 错误
- 空态：图标 + 一句说明 + 一个行动按钮。
- 加载：骨架屏（slate-100 块）。
- 错误：明确文案 + 恢复路径，不静默。

## 4. 组件规范

### 4.1 按钮
| 类型 | 样式 |
|---|---|
| 主按钮 PrimaryButton | `bg-emerald-600 text-white hover:bg-emerald-700 rounded-lg` |
| 次按钮 GhostButton | 边框 `border-slate-200 text-slate-600 hover:border-emerald-300 hover:text-emerald-600` |
| 危险操作 | `text-red-600 hover:bg-red-50` |
| 文本操作 | `text-emerald-600 hover:underline` |

### 4.2 卡片
统一标题结构：左 = 标题（14 semibold，可带图标容器），右 = 操作区。卡片标题与内容之间固定 16 间距。
卡片内部分级：焦点卡（渐变底/大数字）> 常规卡（白底）> 次级块（浅灰底）。

### 4.3 表格
- 表头：`bg-slate-50 text-slate-500 text-xs`，下边框 slate-200。
- 行高 36–40；hover `bg-slate-50`；选中 `bg-emerald-50/60`。
- 语义列（状态/结果）：徽章表达，不用纯文字。
- 数字/ID 用 mono。

### 4.4 徽章（状态语义）
| 语义 | 样式 |
|---|---|
| 成功/通过 | `bg-emerald-50 text-emerald-600` |
| 警告/部分 | `bg-amber-50 text-amber-600` |
| 失败/阻断 | `bg-red-50 text-red-600` |
| 信息/中性 | `bg-slate-100 text-slate-500` |

### 4.5 环节/步骤状态条
横向一排，每环节 = 图标容器 + 名称 + 状态点/完成度。状态点：绿实心=完成、绿空心=进行、灰=待办、红=阻断。点击进入对应页。**不铺文字描述**（交互本身表达，避免信息过载）。

### 4.6 对象状态条（轴心）
全局当前被测对象 + 其各环节完成度：`被测对象名 + [生成 ●][用例 ●][执行 ○][门禁 ▲][报告 ○][成本 ●]`。让"轴心 + 状态"一眼可见。

## 5. 页面模式

| 模式 | 设计要点 | 代表页 |
|---|---|---|
| 总览/焦点 | 一页一焦点 + 环节状态条 + 次级收敛 | 被测对象、生成 |
| 清单 | 查询条件区 + 表格 + 计数 | 用例、历史、报告、成本 |
| 配置/平台 | 表单/设置为主，面包屑可不显示 | 团队、模型、CI/CD、系统设置 |
| 流程向导 | 六步状态条 + 当前步骤内容 + 上一步/下一步 | 上游源与生成 |

---

## 6. 样板页落地标准（被测对象页）

按本规范重构被测对象页，作为全站样板：
1. **一页一焦点**：右侧只保留 1 个焦点主卡（当前被测对象画像），其余（环节、场景、质量、风险）降级为状态条/次级块。
2. **环节状态条**：围绕当前被测对象的 8 环节，只显示状态点 + 数字，不铺文字。
3. **统一色彩**：选中/链接/主按钮全 emerald，红/琥珀仅表失败/警告，页面内不再用 indigo。
4. **状态可见**：被测对象门禁通过率、未决风险、环节完成度都有明确状态色。
5. **密度收敛**：AI 生成过程还原、质量评分、风险明细压缩为次级区块，不再 6 卡平铺。

> 样板经确认后，将本规范推广到全部页面（用例/执行/门禁/历史/报告/成本/追溯/CI 等），统一 token 与交互。
